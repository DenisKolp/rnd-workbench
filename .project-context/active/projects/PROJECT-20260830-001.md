# RnD Workbench

## Summary

RnD Workbench is a local-first macOS knowledge and voice assistant. Its default runtime pipeline is microphone → energy VAD → Whisper/MLX → Qwen/MLX → OmniVoice/GGML Metal → speakers. Users can explicitly route the text generation stage to an OpenAI-compatible API while audio, STT, TTS, storage and background automations stay local. The native SwiftUI utility also manages workspaces, tasks, sources, memory, skills, artifacts, automations and approvals.

The desktop surface includes both a full workspace and a 400 × 238 floating compact window. They are mutually exclusive states backed by one draft and one controller, so returning to the full view does not create a duplicate window. The compact window can switch between interruptible voice control and a small chat showing the latest messages.

## Boundaries

- User audio, documents, memory and history stay on the Mac. Text reaches a
  remote provider only after explicit external-route configuration and within
  the scope disclosed in settings.
- The Python backend lives in `src/voice_assistant`; the native UI lives in `macos`.
- Barge-in is a core interaction: nearby speech cancels generation and TTS, then immediately starts a new turn.
- External capabilities must not claim success until they are explicitly connected and approved.

## Verification

Run `uv run pytest`, type-check the SwiftUI source, build with `zsh macos/build.sh`, and perform a visual smoke test of the resulting application.
