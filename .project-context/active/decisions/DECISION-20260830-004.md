# Capability-aware RnD Workbench system identity

## Context

The previous system prompt only described a generic Russian voice assistant. It
did not explain the product identity, text and voice channels, local-first data
boundary, workspace context or the distinction between LLM output and actions
performed by the surrounding application.

## Decision

Give the model a shared Russian system prompt defining RnD Workbench's purpose,
local runtime, voice interruption behavior, workspaces, tasks, memory, imported
sources, chunk-level local search, structured meetings, the deterministic
Attention Engine, skills, artifacts, automations and approvals. Explicitly state
that the LLM has no direct function-calling API and must never claim an interface
operation, external action or draft was executed without confirmation.

Keep responses speech-friendly by default while allowing structured Markdown for
document-producing skills. Increase the output allowance from 220 to 512 tokens
so research and document tasks are not truncated immediately.

## Verification

The project configuration test loads the deployed prompt and asserts both the
RnD Workbench voice identity and capability section are present.
