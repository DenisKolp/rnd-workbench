# Task-scoped sources with durable provenance and terminal task recovery

## Context

A file attached from the universal task composer was previously promoted to the
whole Workspace. That violated CTX-01 because another task in the same Workspace
could retrieve it. Source references used during one answer were transient, so
the UI could not reliably restore provenance after switching tasks or restarting.
Exceptions could also leave a task indefinitely in `running`.

## Decision

Add a migrated `sources.visibility` field with `workspace` and `task` values and
a `task_sources` relation. Imports made from an active task are task-only;
Workspace imports remain Workspace-wide. Source search receives the current task
ID, includes its linked task sources, and excludes task-only sources belonging to
other tasks.

Persist the source contract `{id, title, kind, path}` and active Skill in each
assistant message metadata. Emit the same contract in task context and assistant
start events so SwiftUI can restore clickable source chips from a snapshot.

Treat task state as durable operational data. Text or voice exceptions end the
task as `error` with a task event and audit record. An interrupted answer ends as
`needs_user`. At startup, persisted `running` tasks are recovered to
`needs_user`, also with an event and audit record, because no prior model process
can still be executing them.

## Consequences

- Task attachments no longer leak into sibling tasks through Workspace search.
- Citations remain inspectable after task switching and application restart.
- Existing databases migrate in place and preserve prior sources as
  Workspace-visible.
- A task cannot silently remain `running` after a model failure, interruption or
  application restart.

## Verification

The Python suite exercises migration, task isolation, durable message metadata,
UI event source contracts, text/voice failures, interruption status and startup
recovery. All 44 tests pass.
