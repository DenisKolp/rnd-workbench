# Continuous OmniVoice playback with nonfatal speech recovery

## Context

Each sentence previously opened and closed CoreAudio independently, while the
vendor streaming postprocessor inserted a perceptible 100 ms exact-zero gap at
internal decoder boundaries. A synthesis failure could also return HTTP 200
with no PCM. Treating that TTS-only failure as a failure of the whole task then
discarded a useful distinction: the complete text could already be generated
and persisted even though playback failed.

## Decision

Use one player stream for the complete answer and independent synthesis and
playback workers so the next sentence can be prepared while current audio is
playing. Ship a desktop-realtime OmniVoice postprocess profile with a 60 ms
crossfade window and 20 ms edge fade/pad; retain the upstream 300/100 ms values
through `OMNIVOICE_STREAM_POSTPROC_PROFILE=upstream` for rollback.

Count received PCM samples in the Python backend. Treat a completed HTTP 200
with zero samples or an incomplete PCM stream as an explicit error with the
server stderr tail, while keeping intentional cancellation non-error. On vendor
synthesis failure, close the chunked response without a successful terminating
chunk.

Keep a TTS-only failure nonfatal to the text result. Preserve the full answer,
complete the task as `done`, emit `speech_error`, and include `spoken` and
`tts_error` in `assistant_end`; emit `speech_recovered` after a later successful
attempt. `retry_speech` replays the last assistant text without invoking the LLM
and without creating a task or message in SQLite. Full and compact interfaces
share `rnd.speakReplies` and present the same recoverable inline error state.

## Consequences

- Sentence boundaries no longer reopen the audio device or add app-side fades.
- Internal safety fades remain long enough to suppress clicks but are much less
  likely to sound like dropouts.
- «Text appears but there is no audio» is now diagnosable and recoverable without
  converting a successful text response into a failed task.
- Retrying speech is idempotent with respect to LLM inference and persisted
  conversation state.

## Verification

The 90-test Python suite covers one player call, synthesis/playback overlap,
cancellation races, empty HTTP 200, partial PCM, nonfatal full-text completion,
the recovery event contract and retry without LLM or database writes.

Bundled **0.7.0 build 5** produced its first audio after 0.472 seconds and
synthesized 8.760 seconds of speech in 1.939 seconds (RTF 0.221), peak 0.884094,
zero clipped samples. Cancellation completed in 0.229 seconds and Whisper
loopback exactly matched the source text.
