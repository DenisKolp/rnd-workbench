# Fast OmniVoice on Apple Silicon through GGML Metal

## Context

Qwen3-TTS produced audible distortion even after the output path gained headroom,
a limiter and edge fades. The CUDA/vLLM project named `omnivoice-fast` cannot run
on the current Apple Silicon Mac: its published 115 ms result requires an H100.

## Decision

Use the same OmniVoice 0.6B weights through the MIT-licensed
`ServeurpersoCom/omnivoice.cpp` runtime. Build its Q8 GGUF server against GGML
Metal, keep one model context resident on `127.0.0.1`, request PCM16 streaming,
use 16 MaskGIT steps and 2.5 second internal chunks, and close the HTTP stream on
barge-in. Keep Qwen3-TTS and macOS `say` as configuration fallbacks.

The official OmniVoice weights are CC-BY-NC. This backend is enabled for local
personal/R&D evaluation; corporate or commercial deployment needs a rights review.

## Verification

On the current Apple M5 Pro, the warmed Russian benchmark loaded in 0.31 s,
emitted its first audio after 0.50 s, generated 9.01 s of speech in 2.70 s
(RTF 0.30), peaked at 0.873 and contained zero full-scale samples. Cancellation
returned control in 0.22 s, and the next request resumed. An OmniVoice → Whisper
loopback recovered the complete Russian test sentence exactly in both cold and
warm runs.
