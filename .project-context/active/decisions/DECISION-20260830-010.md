# Versioned Markdown artifacts with provenance and Quick Actions

## Context

Artifact files already received monotonically numbered Markdown revisions, but
the runtime could not list or restore versions and did not record which task,
source or earlier artifact produced a particular revision. Results also lacked
structured post-result actions.

## Decision

Migrate to schema v4. Add version metadata and explicit artifact relations for
`produced_by_task`, `derived_from_source`, `derived_from_artifact`,
`revision_of` and `restored_from`. Restoring an older Markdown version always
creates a new latest revision, preserving immutable history.

Expose backend contracts to list versions and relations, restore a version and
run safe local Quick Actions such as saving a plain task result as an artifact
or into working memory. Include applicable actions in snapshots and the final
assistant event.

## Consequences

- The current file can be rolled back without deleting later work.
- Provenance is queryable at artifact-version granularity.
- Native UI controls and additional DOCX/XLSX/PPTX renderers can build on a
  stable contract; those binary formats are not claimed by this iteration.

## Verification

Regression tests cover version listing, immutable restore, monotonic numbering,
all relation types, Quick Action commands, final-event contracts and migration
from the previous schema. A copied live schema-v3 database migrated to v4 with
integrity `ok` and zero foreign-key violations.
