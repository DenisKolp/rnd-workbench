# ADR-0003: серверная граница eXpress BotX

- Status: accepted for pilot source milestone 0.9.15
- Date: 2026-09-01
- Scope: read-only meeting intake

## Context

Первый корпоративный сценарий RnD Workbench — получить стенограмму встречи
eXpress, дополнить её описанием и вложениями и подготовить решения, поручения,
риски и следующую встречу. Desktop-клиент eXpress уже установлен у пользователя,
но его сессия, cookies, кэш и токены не являются поддерживаемым интеграционным
контрактом. Публичный webhook в desktop-приложении также создавал бы ненужную
сетевую поверхность.

Официальный Bot API v4 доставляет callback зарегистрированному боту, а BotX API
позволяет боту скачать файл по `group_chat_id` и `file_id`. Recordings Bot может
передавать стенограмму как редактируемый документ, поэтому нормализованный пакет
должен принимать DOCX без облачного преобразования.

## Decision

1. Входящий `POST /command` принимает только отдельный корпоративный intake
   service. macOS/Windows-клиент остаётся исходящим read-only потребителем
   нормализованных пакетов.
2. Inbound JWT проверяется до использования payload: только `HS256`, точные
   BotX FQDN и bot UUID, integer timestamps, `nbf = iat`, TTL не более 90 секунд
   и уникальный `jti` в ограниченном fail-closed replay-cache.
3. JSON, UUID, имена, MIME, количество и размеры файлов проходят строгую
   валидацию. Неоднозначная стенограмма блокирует событие.
4. Поле `file` из callback не переносится в план, БД или журнал. Загрузка строится
   заново через тот же доверенный BotX host по проверенным `group_chat_id` и
   `file_id`, с отдельным коротким outbound JWT `version = 2`.
5. Секрет бота остаётся только в памяти сервисного процесса и поступает из
   deployment vault. В репозитории, desktop-настройках и диагностике его нет.
6. На этом этапе интеграция read-only. Ответы в eXpress и действия в Jira/Kaiten
   требуют отдельного autonomy gate, предпросмотра и idempotency journal.
7. Python обрабатывает BotX/package content, потому что этот слой уже владеет
   безопасным импортом и анализом документов. Java 21 сохраняет роль общей
   metadata-only политики и журнала внешних эффектов; содержимое стенограмм в
   JVM не передаётся.

## Consequences

- Сценарий можно развернуть без доступа к внутренностям desktop-клиента eXpress.
- Один и тот же нормализованный пакет работает для локального fallback и
  корпоративной доставки, сохраняя provenance и идемпотентность.
- Наличие модуля в исходниках не считается живым подключением. Для пилота всё
  ещё нужны зарегистрированный BotX bot, HTTPS endpoint, vault, allowlist,
  обезличенная тестовая конференция и проверка прав доступа.
- In-memory replay-cache достаточен для одного стендового процесса. Перед
  горизонтальным production-развёртыванием нужен общий атомарный TTL-store.

## Verification

Контрактные тесты подписывают реальные HS256 JWT, проверяют identity/lifetime,
replay, duplicate JSON keys, границы файлов, выбор стенограммы, отсутствие
подписанного URL в плане, outbound v2 JWT и точный Files API path. Отдельные
тесты импортируют валидный и повреждённый DOCX и подтверждают rollback до
создания контекста.
