# RnD Workbench — текущее состояние

Контрольная точка: 1 сентября 2026 года.

Следующая цель и критерии пилота описаны в
[`docs/PILOT_PRODUCT_CONTRACT.md`](docs/PILOT_PRODUCT_CONTRACT.md).

RnD Workbench — локальный по умолчанию персональный рабочий ИИ-ассистент с
нативным интерфейсом, полноэкранным и компактным режимами, единым текстовым и
голосовым контуром, локальной базой знаний и управляемым контекстом задач.

## Что уже работает

- голосовой pipeline `Whisper → LLM → OmniVoice-Fast` с потоковой генерацией,
  перебиванием и короткой озвучиваемой версией полного текстового ответа;
- единый голос OmniVoice для всех фрагментов ответа, фильтрация проблемных для
  синтеза символов и повтор озвучивания без повторного LLM-запроса;
- локальная allowlist-телеметрия качества голоса для macOS и Windows: задержки
  от конца речи, готовность захвата, peak/clipping и перебивание; полный UI
  показывает 14-дневную сводку и экспортирует только агрегаты без содержимого;
- локальная дневная агрегация полезности пилота для обеих платформ: активные
  дни, завершённые голосовые/текстовые запросы, диктовка, импорт и briefing
  встреч, время первого результата и оценка 1–5. В полном UI блок свёрнут по
  умолчанию; compact-виджет не получил новых элементов;
- durable content-free учёт жизненного цикла сессий macOS/Windows: следующий
  запуск распознаёт незавершённую предыдущую сессию, повторные start/quit
  идемпотентны, а в UI и JSON выходит только агрегат crash-free без внутренних
  идентификаторов;
- кроссплатформенный preflight устройства с двенадцатью проверками и итогом
  `ready` / `limited` / `blocked`; подробности свёрнуты по умолчанию, а
  результаты не содержат запросов, транскриптов и ответов;
- единый content-free onboarding macOS/Windows: по статусам preflight и только
  агрегированным счётчикам он ведёт к первому результату, голосовой реплике,
  импорту встречи и сводке. Показывается в полном диагностическом контуре и
  не усложняет compact-виджет;
- рабочие пространства, задачи, планы, история, статусы, события и локальный
  аудит;
- прикрепление нескольких файлов прямо к следующему запросу и изоляция их в
  контексте задачи;
- локальный поиск по фрагментам с точными позициями и переходом к источнику;
- импорт текста и аудиозаписей встреч, локальная транскрибация и структурированный
  разбор решений, поручений, рисков и вопросов;
- локальный импорт папки/ZIP встречи eXpress («Синапс») с отдельными источниками
  транскрипта, описания и вложений; однозначный быстрый набор не требует ручного
  `manifest.json`; дополнительно реализован выключенный по умолчанию read-only
  корпоративный intake для macOS/Windows с HTTPS allowlist, SHA-256,
  идемпотентностью и durable cursor. Он считается подключённым только после
  успешной проверки реального endpoint;
- явные серии встреч eXpress по `series_id`/`group_chat_id`: briefing не
  смешивает одноимённые встречи, сравнивает выбранную с предыдущей в той же
  серии и готовится автоматически; без series ID используется только выбранная
  встреча. Windows-панель показывает анализ, briefing и безопасное удаление;
- глобальная push-to-talk диктовка: удержание клавиши записывает речь, отпускание
  вставляет текст в активное редактируемое поле без системного буфера обмена;
- память, скиллы, навыки, материалы с версиями и provenance-связями,
  автоматизации, уведомления и центр согласований;
- безопасные цепочки внешних действий: предпросмотр, риск, подтверждение,
  журнал шагов, Java-резервирование до вызова исполнителя и явная ошибка, если
  реальный исполнитель не подключён;
- Java 21-политика автономности теперь подключена к общему integration hub:
  через IPC уходит только категория действия, решение сверяется с Python,
  повторно проверяется непосредственно перед connector call, расхождение
  блокирует вызов, а видимый fallback сохраняет прежние безопасные уровни при
  недоступном companion;
- локальные, пользовательские корпоративные и внешние OpenAI-совместимые модели
  с классификацией данных и явной границей передачи контекста;
- Project Context Router для долговременного контекста разработки.
- UI/UX-аудит полного и компактного macOS-потока: быстрые действия оставлены
  только рядом с конкретной задачей, компактный чат освобождён от лишней панели,
  длинное служебное уведомление убрано из шапки voice-first виджета, а переход
  из полного окна сокращён до однозначной кнопки «Виджет».
- Windows Electron shell в исходниках: compact 410×420 и full являются
  состояниями одного `BrowserWindow`; WebAudio capture/playback, Faster-Whisper,
  один короткий OmniVoice-Fast TTS-запрос и barge-in проходят source contracts.
  Визуальный аудит production renderer в compact 410×420 и full 1120×760
  подтвердил отсутствие прокрутки страницы и переполнения видимых кнопок;
  переключение названо «Развернуть»/«Виджет», локальный контур выбран
  безопасным начальным значением, а техническое название STT убрано с кнопки
  импорта.
  Готовые транскрипты, локальные аудиофайлы и папки/ZIP eXpress импортируются;
  Windows CI собирает unsigned voice-ready portable package и запускает
  packaged backend smoke-test. Capability голоса остаётся выключенной без
  локальных весов Whisper и OmniVoice-Fast server; Windows voice hardware QA и
  подписанная пилотная сборка ещё не выполнены.
- Java 21 `core-java` содержит общие политики, executable stdio JSONL 1.0 и
  persistent SQLite idempotency journal. macOS и Windows backend запускают
  metadata-only route gate до LLM, а обе сборки включают ограниченный `jlink`
  runtime; Python fallback видим пользователю и несовпадение политик блокирует
  запрос. В macOS compact/full фактическая политика видна рядом с маршрутом;
  внешний публичный API требует отдельного opt-in, уровня `public` и явного
  выбора. Общий integration hub теперь резервирует production-действие через
  Java `action.claim`, записывает безопасный результат через `action.complete`
  и при перезапуске проверяет `action.inspect` без автоматического повтора
  внешнего эффекта. При недоступности журнала production-действие блокируется;
  состояние сверки видно в macOS и Windows UI.

## Архитектура и границы

Локальный режим является базовым и не требует отправки рабочих данных внешнему
провайдеру. STT, TTS, исходное аудио, импортированные файлы и SQLite-хранилище
остаются на устройстве. Внешний или корпоративный текстовый маршрут включается
явно и получает только допустимый классификацией и выбранной областью контекст.

Email, корпоративный календарь, Jira/Kaiten, Confluence и другие рабочие системы
в текущей контрольной точке не имеют подключённых production API-исполнителей.
Для eXpress готов read-only клиент корпоративного intake, но без выданного
endpoint/токена и стендовой проверки он также остаётся неподключённым. Приложение честно
создаёт план и запрос согласования, но не сообщает о несуществующем успехе.

Репрезентативная короткая реплика OmniVoice прошла контроль с первым звуком
0,706 с, RTF 0,199, фактической остановкой `AudioPlayer` после перебивания
0,116 с, восстановлением первого аудиоблока за 1,360 с, WER 0 и нулём
clipped/click samples. Эти цифры подтверждены на текущем reference-устройстве и
не заменяют будущую матрицу замеров на устройствах пилотной группы.

## Что не хранится в Git

Локальные веса моделей, собранные runtime-бинарники, пользовательская SQLite,
аудиотесты, резервные копии, виртуальное окружение и `node_modules` исключены из
репозитория. Они восстанавливаются по инструкции сборки и не должны попадать в
историю исходного кода.

## Проверка

Основной набор запускается командой:

```bash
PYTHONPATH=src .venv/bin/python -m pytest
```

Нативный интерфейс проверяется contract-тестами, компилируется и ad-hoc
подписывается скриптом `zsh macos/build.sh`. Итоговый HTML-обзор системы
выпускается только после завершения проекта и не входит в эту промежуточную
контрольную точку.

Полный Python/UI-набор содержит 464 теста и проходит; в него входят 30 macOS, 74
Windows contract-теста и Python ↔ Java golden contracts. Отдельные 45
JUnit-теста `core-java` проходят локально и в Linux CI на JDK 21/Gradle 9.7.1.
Windows job собирает `jlink` runtime, выполняет реальные route/action journal
IPC probes и проверяет их из packaged backend. Отдельный macOS job парсит Swift shell, собирает
`jlink` и проверяет реальный local/corporate/public-external IPC; локальная
5,1-ГБ `.app` собрана, строго проверена `codesign` и прошла GUI-smoke с одним
окном. Реальный Windows hardware QA и production-подпись по-прежнему обязательны
перед пилотной поставкой.
