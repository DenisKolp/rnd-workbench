# RnD Workbench — локальный по умолчанию ИИ-ассистент для Apple Silicon

Персональный и голосовой помощник для macOS с локальным маршрутом по умолчанию:

`микрофон → energy VAD → Whisper/MLX → Qwen/MLX → OmniVoice/GGML Metal → динамики`

После загрузки весов локальному маршруту сеть не нужна. Whisper, OmniVoice,
аудио и TTS всегда остаются на Mac; локальная Qwen также входит в `.app`.
Пользователь может явно подключить OpenAI-совместимую внешнюю LLM: тогда только
перечисленный в настройках текстовый контекст отправляется выбранному
провайдеру. Рабочие данные хранятся в
`~/Library/Application Support/LocalVoiceAssistant/`.

Текущая сборка — **0.8.0 (build 6)**.

## Возможности приложения

- «Сегодня», рабочие пространства, задачи, структурированные встречи, локальные
  исследования и единый центр внимания.
- Постоянная SQLite-история задач, сообщений, источников, памяти и аудита.
- Импорт документов, готовых транскриптов и аудиозаписей встреч; аудио локально
  нормализуется и распознаётся Whisper, затем автоматически создаётся карточка.
- Локальный поиск и цитаты `[S1]`.
- Локальный разбор встреч на темы, решения, поручения, обязательства, риски и
  вопросы с исполнителями, сроками и точными позициями в транскрипте.
- Attention Engine с объяснимым приоритетом, просрочками, ссылками на источник,
  briefing перед встречей и сравнением двух встреч.
- Скиллы `/research`, `/meeting`, `/briefing`, `/digest`, `/document` и их пользовательские версии.
- Markdown-артефакты с локальным редактором; backend уже поддерживает версии,
  восстановление и provenance-граф, но нативный SwiftUI-интерфейс этих операций
  пока не подключён.
- Автоматизации по расписанию или событию «при новом источнике».
- Согласования для значимых действий; неподключённые системы не имитируют успех.
- Единый текстовый и голосовой pipeline с потоковой озвучкой и перебиванием.
- Подтверждаемое удаление задач, источников, встреч и материалов. Управляемые
  копии файлов перемещаются в Корзину macOS; исходный выбранный файл не меняется.
- «Уведомления» объединяют готовые результаты, изменения контекста и ошибки.

## Стек по умолчанию

- STT: `whisper-large-v3-turbo`, MLX, русский язык.
- LLM по умолчанию: `Qwen3-4B-Instruct-2507`, 4-bit, MLX; опционально — явно
  настроенная OpenAI-совместимая API без скрытого переключения маршрута.
- TTS: `OmniVoice 0.6B`, Q8 GGUF, нативный GGML/Metal-сервер, русский язык.
- Turn detection: адаптивный energy VAD, 30-миллисекундные блоки.

На Mac с M5 Pro и 24 ГБ памяти модели помещаются одновременно с хорошим запасом.

## Установка

Нужны Homebrew, `uv`, CMake и PortAudio:

```bash
brew install cmake portaudio
uv sync --python 3.12 --extra dev
```

## Нативная macOS-утилита

Готовое самодостаточное приложение находится рядом с папкой проекта:
`RnD Workbench.app`. Оно показывает рабочее пространство ассистента и
остаётся доступным через иконку в menu bar.

Из основного окна или menu bar можно открыть компактное плавающее окно в правом
нижнем углу. В нём есть два режима: «Голос» с управлением прослушиванием и
перебиванием и «Чат» с последними сообщениями и строкой ввода. Окно остаётся
поверх других приложений, перемещается перетаскиванием за фон и разворачивается
обратно в полное рабочее пространство. Полный и компактный вид — два состояния
одного приложения: переход закрывает предыдущее окно и сохраняет общий черновик.
Комбинация `⌘⇧M` указана рядом с командой
компактного окна в меню приложения.
Полное и компактное окна используют одну настройку озвучивания
`rnd.speakReplies`; кнопка с динамиком одновременно переключает её в обоих
режимах. Если TTS недоступен, готовый текст остаётся в истории, а задача
завершается успешно. В интерфейсе появляется неблокирующий баннер с командой
«Повторить озвучивание»: она воспроизводит последний ответ повторно, не вызывает
LLM и не создаёт новую задачу или сообщение в базе.
Первый запуск может запросить доступ к микрофону. В голосовом режиме ассистента
можно перебить обычной речью: озвучка остановится, а новая реплика сразу пойдёт
в Whisper. Прерванная фраза помечается в истории как «перебито».

Пересобрать приложение после изменения SwiftUI или Python backend:

```bash
zsh macos/build.sh
```

Сборщик компилирует OmniVoice под Metal, включает runtime, зависимости, исходный
код и локальные модели внутрь пакета приложения и подписывает его ad-hoc подписью.

Проверка окружения:

```bash
uv run local-voice --self-test
uv run local-voice --list-devices
uv run local-voice --loopback-test
```

Запуск:

```bash
uv run local-voice
```

macOS запросит доступ к микрофону для Terminal или Codex. Первую секунду после
запуска нужно сохранять тишину: в это время калибруется VAD.

Один голосовой запрос и выход:

```bash
uv run local-voice --once
```

Проверка без микрофона и Whisper:

```bash
uv run local-voice --text "Коротко объясни, почему небо синее"
```

## Настройка

Все параметры находятся в `config.toml`. Если выбрано неверное устройство:

```bash
uv run local-voice --list-devices
```

Затем укажите индексы:

```toml
[audio]
input_device = 1
output_device = 2
```

В шумной комнате увеличьте `noise_multiplier` до `4.0`. Если начало тихой речи
не ловится, уменьшите `min_rms` до `0.003` и `noise_multiplier` до `2.2`.

Для TTS по умолчанию оставлен 14-процентный запас по уровню (`output_gain = 0.86`).
Перед выводом работает лимитер с потолком 0.94. Весь ответ проигрывается через
один CoreAudio stream, а следующая фраза синтезируется параллельно текущему
воспроизведению: аудиоустройство больше не закрывается и не открывается на каждой
границе предложения. Если конкретные динамики всё ещё звучат жёстко, уменьшите
`output_gain` до `0.75`–`0.80`.

OmniVoice запускается как постоянный локальный сервер только на `127.0.0.1`.
Параметр `steps = 16` даёт быстрый режим, а `chunk_duration_s = 2.5` управляет
размером потоковых фрагментов. Для desktop-realtime профиля внутренний crossfade
сокращён до 60 мс (20 мс fade-out, 20 мс защищённой паузы, 20 мс fade-in), а
краевой fade/pad — до 20 мс. Исходный профиль доступен для мгновенного отката:

```bash
OMNIVOICE_STREAM_POSTPROC_PROFILE=upstream uv run local-voice
```

В A/B тесте desktop-профиль синтезировал 17,43 с речи за 4,42 с (RTF 0,253),
сократил суммарную длительность той же реплики на 0,4 с, сохранил пик 0,906 и
0 обрезанных сэмплов. Whisper одинаково распознал обе версии.

Контроль bundled runtime в **0.8.0 build 6**: первый аудиоблок через 0,425 с,
8,610 с речи синтезированы за 2,156 с (RTF 0,250), peak 0,873138,
0 clipped samples. Отмена завершилась за 0,229 с, а первый блок после
восстановления пришёл через 0,928 с. В предыдущем loopback-контроле Whisper
точно воспроизвёл текст тестовой реплики.

Проект `pavanyellow/omnivoice-fast` с заявленными 115 мс рассчитан на CUDA/H100
и vLLM и не запускается на macOS. Здесь используется быстрый нативный порт
`ServeurpersoCom/omnivoice.cpp` для Metal с теми же весами OmniVoice.

Перебивание включено через `assistant.barge_in_enabled`. Оно срабатывает примерно
после 300 мс близкой речи. Во время воспроизведения действует отдельный абсолютный
порог `barge_in_playback_min_rms = 0.032`, а адаптивный порог учитывает утечку и
громкость фактически проигрываемых блоков TTS. Ссылка на громкость удерживается
500 мс, чтобы перекрыть короткие паузы между потоковыми фрагментами, а первые
600 мс ответа отведены на безопасную оценку акустического эха. Эти ограничения
не применяются, пока модель только формирует ответ, поэтому перебивание без
звучащего TTS остаётся чувствительным. С наушниками оно ещё надёжнее.

Если помощник всё равно перебивает сам себя, сначала увеличьте
`barge_in_playback_min_rms` до `0.04`, затем при необходимости
`barge_in_echo_multiplier` с `2.1` до `2.3`. Если он плохо слышит тихое
перебивание — уменьшите абсолютный порог до `0.025`, не меняя обычный `min_rms`.

### Внешняя языковая модель

В «Настройках» можно выбрать «Внешняя API», указать HTTPS-адрес
OpenAI-совместимого `/chat/completions`, идентификатор модели и API-ключ.
Удалённые адреса требуют HTTPS; незашифрованный HTTP разрешён только для
loopback-сервера на этом Mac. Ключ привязан к каноническому endpoint и хранится
в Связке ключей macOS, а не в SQLite, событиях или логах.

По умолчанию внешней модели доступны системные и служебные инструкции, название
текущего пространства, активный скилл, запрос, история текущей задачи и только
вручную прикреплённые или явно `@`-упомянутые источники. Расширение до контекста
пространства требует отдельного выбора и сбрасывается при смене endpoint или
пространства. Автоматизации продолжают выполняться локальной MLX-моделью.

### Быстрый системный TTS

Для отладки без загрузки нейросетевого TTS:

```toml
[tts]
backend = "macos"
voice = "Milena"
```

Имена установленных голосов можно посмотреть командой `say -v '?'`.

Для возврата к прежнему Qwen3-TTS укажите `backend = "qwen3"`, модель
`models/qwen3-tts`, язык `Russian` и голос `Serena`.

## Идентичность агента

Системный промпт хранится в `config.toml` и продублирован безопасным значением по
умолчанию в `src/voice_assistant/config.py`. Он объясняет модели, что она —
локальный RnD Workbench, принимает голос и текст, знает о рабочих пространствах,
задачах, памяти, документах, локальном поиске, skills, артефактах, автоматизациях
и согласованиях. Промпт также явно фиксирует границу: прямого function calling у
LLM пока нет, поэтому она не должна выдавать UI-операцию или черновик за
выполненное действие.

## Задержка

Приложение распознаёт законченную реплику после 650 мс тишины. Текст LLM
генерируется потоково; готовые фразы сразу передаются TTS в отдельном потоке,
поэтому озвучка начинается до завершения всего ответа. Фактическая задержка
зависит от длины запроса, температуры Mac и первого прогрева моделей.

Во время генерации и озвучивания микрофон остаётся активным. VAD использует
защитный grace-период и оценивает утечку голоса ассистента в микрофон; обнаружив
более близкую речь, он отменяет LLM/TTS и сохраняет начало новой реплики. TTS
выводится блоками по 30 мс, поэтому уже обнаруженное перебивание глушит звук почти
сразу. Это лёгкая защита от эха, а не полноценный AEC: на высокой громкости
встроенных динамиков может потребоваться настройка порога.

## Тесты

```bash
uv run pytest
```

Для build 6 полный Python-набор завершился результатом **138 passed**; Swift
typecheck, 18 endpoint-canonicalization self-tests и строгая рекурсивная
проверка подписи `.app` также прошли. Live SQLite-база мигрирована до schema v4:
`integrity_check = ok`,
нарушений foreign key нет, 65 source chunks соответствуют 65 строкам FTS.
Таблица `artifact_relations` активна; 0 связей в текущих пользовательских данных
является нормальным пустым состоянием.

Backend сообщает отказ озвучивания отдельными событиями `speech_error` и
`speech_recovered`; финальное событие ответа содержит `spoken` и `tts_error`.
Эти контракты и повторная озвучка без нового LLM-запроса и без записи в базу
покрыты regression-тестами.

Контрольный синтез с метриками и WAV:

```bash
PYTHONPATH=src .venv/bin/python scripts/benchmark_omnivoice.py
```

По контрольному скриншоту окна 1060×720 исправлено переполнение русских подписей:
заголовок события допускает две строки, действие вынесено в нижний ряд и не
сжимается, а верхняя панель выбирает компактную подпись. Полная ручная проверка
VoiceOver и всех состояний остаётся отдельным релизным шагом.

## Контекст проекта через MCP

Для памяти разработки подключён `mcp-project-context-router`. Он установлен как
локальная dev-зависимость, хранит долговременные записи в `.project-context` и
запускается Codex как проектный MCP-сервер через `.codex/config.toml`.

```bash
npm run context:index
npm run context:doctor
```

После первой установки или изменения `.codex/config.toml` откройте проект в новом
сеансе Codex, чтобы конфигурация MCP была перечитана. Интеграция обслуживает
контекст разработки и не входит в пользовательский runtime приложения.
