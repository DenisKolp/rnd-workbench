# RnD Workbench — local-first рабочий ИИ-ассистент

RnD Workbench — независимый исследовательский прототип, не официальный продукт
и не подтверждённый корпоративный бренд. Визуальная палитра вдохновлена
публичными индустриальными референсами; товарные знаки и фирменные элементы
третьих лиц в репозиторий не включены.

Текущая продуктовая цель — пилот на 30 сотрудниках с macOS и Windows, где
основным входом служит быстрый компактный голосовой виджет, а полное окно
показывает детали работы, источники и согласования. Измеримые критерии и границы
автономности зафиксированы в
[`docs/PILOT_PRODUCT_CONTRACT.md`](docs/PILOT_PRODUCT_CONTRACT.md).
Самодостаточный визуальный обзор с актуальными скриншотами выпускается только
после завершения системы и намеренно не входит в эту промежуточную контрольную
точку.

Проверенная референсная голосовая сборка сейчас работает на macOS Apple Silicon.
Windows-клиент реализован на Electron; его source vertical уже включает
WebAudio, Faster-Whisper, OmniVoice-Fast и перебивание. Windows CI собирает
unsigned voice-ready portable package и проверяет импорт Faster-Whisper,
CTranslate2 и Tokenizers непосредственно из packaged backend. Веса Whisper и
локальный OmniVoice-Fast server остаются внешними deployment-компонентами;
акустический hardware QA и подпись установщика ещё не выполнены. Этот статус не
выдаётся за готовую пилотную поставку.

Референсный локальный голосовой контур macOS:

`микрофон → energy VAD → Whisper/MLX → Qwen/MLX → OmniVoice/GGML Metal → динамики`

После загрузки весов локальному маршруту сеть не нужна. Исходное аудио, STT и
TTS остаются на устройстве; текстовый inference может выполняться локальной,
корпоративной или явно подключённой внешней OpenAI-совместимой моделью согласно
классификации данных. На macOS рабочие данные хранятся в
`~/Library/Application Support/LocalVoiceAssistant/`; Windows-клиент использует
каталог приложения в `%LOCALAPPDATA%`.

Текущая macOS-сборка — **0.9.11 (build 19)**.

## Возможности приложения

- «Сегодня», рабочие пространства, задачи, структурированные встречи, локальные
  исследования и единый центр внимания.
- Постоянная SQLite-история задач, сообщений, источников, памяти и аудита.
- Импорт документов, готовых транскриптов и аудиозаписей встреч; аудио локально
  нормализуется и распознаётся Whisper, затем автоматически создаётся карточка.
- Импорт локальной папки/ZIP встречи eXpress («Синапс») с раздельным provenance
  транскрипта, описания и вложений, в том числе быстрый однозначный набор без
  ручного `manifest.json`; есть идемпотентность и восстановление после
  незавершённого импорта. Read-only корпоративный intake реализован для обеих
  desktop-оболочек, но остаётся выключен без корпоративного endpoint, токена и
  успешной стендовой проверки BotX/Recordings Bot bridge.
- Локальный поиск и цитаты `[S1]`.
- Локальный разбор встреч на темы, решения, поручения, обязательства, риски и
  вопросы с исполнителями, сроками и точными позициями в транскрипте.
- Attention Engine с объяснимым приоритетом, просрочками, ссылками на источник,
  briefing перед встречей и сравнением двух встреч. Серии eXpress связываются
  только по явному ID (`series_id`/`group_chat_id`), без догадок по названию;
  briefing после импорта формируется автоматически на macOS и Windows.
- Скиллы `/research`, `/meeting`, `/briefing`, `/digest`, `/document` и их пользовательские версии.
- Markdown-артефакты с локальным редактором; backend уже поддерживает версии,
  восстановление и provenance-граф, но нативный SwiftUI-интерфейс этих операций
  пока не подключён.
- Автоматизации по расписанию или событию «при новом источнике».
- Согласования для значимых действий; неподключённые системы не имитируют успех.
- Общая Java 21-политика автономности проверяет каждое чтение, черновик и
  внешнее действие по обезличенной категории, а согласованное действие повторно
  проверяется непосредственно перед connector call. Python и Java должны вернуть
  одинаковый уровень согласования; расхождение блокирует действие до вызова
  коннектора, а недоступный companion явно включает встроенную политику.
- Единый текстовый и голосовой pipeline с потоковой озвучкой и перебиванием.
- Обезличенная локальная диагностика голосового пилота: p50/p95 готовности,
  транскрипта и первого звука, TTS RTF, peak/clipping, программная остановка при
  перебивании и WER на фиксированном русском/корпоративном наборе. Локальная
  цифровая проверка прогоняет 10 фраз через TTS→STT, но не подменяет проверку
  микрофона и акустики. В UI и JSON-экспорте доступны только числовые агрегаты
  без аудио, транскриптов, рабочего содержимого и идентификаторов сессий.
- Обезличенная оценка ежедневной полезности: локальные дневные счётчики активных
  дней, голосовых/текстовых запросов, диктовки, импорта и briefing встреч,
  время до первого результата и одна изменяемая оценка 1–5. Сырые события,
  точные времена активности, документы и идентификаторы не экспортируются;
  блок свёрнут в полном интерфейсе и не усложняет compact-виджет.
- Надёжность сессий считается локально и без рабочего содержимого: приложение
  идемпотентно отмечает start/clean exit, на следующем запуске учитывает
  незавершённую сессию и экспортирует только число завершений и crash-free
  процент. После 20 завершений результат входит в preflight с порогом 99%.
- Детерминированная проверка готовности каждого устройства: хранилище, модели,
  микрофон, голосовые SLO, Java-политика, защита внешних действий, импорт встреч,
  корпоративные подключения и поставка получают честный статус
  `pass` / `warn` / `block` / `unverified`. Проверка не передаёт рабочее
  содержимое и одинаково доступна в macOS и Windows UI.
- Content-free быстрый старт выбирает один следующий шаг из четырёх проверяемых
  этапов: первый полезный результат, голосовой запрос, импорт встречи и сводка.
  Он использует только статусы preflight и агрегированные счётчики, скрыт внутри
  полного диагностического раздела и не добавляет элементы в compact-виджет.
- Диагностика и новая WER-проверка остаются внутри свёрнутого блока полного
  окна. Compact-виджет не получил новых элементов, а Electron-кнопки допускают
  перенос подписи и рост по высоте вместо обрезания текста.
- Подтверждаемое удаление задач, источников, встреч и материалов. Управляемые
  копии файлов перемещаются в Корзину macOS; исходный выбранный файл не меняется.
- «Уведомления» объединяют готовые результаты, изменения контекста и ошибки.

## Кроссплатформенная архитектура

- macOS shell остаётся на SwiftUI, Windows shell реализован только на Electron.
- Compact и full — состояния одного процесса и одного окна, без дублирования
  backend или истории. Electron compact имеет размер 410×420 и отдельные вкладки
  «Голос»/«Чат».
- Платформенно-независимые правила маршрутизации моделей, автономности и
  безопасных внешних действий выделяются в `core-java` на Java 21.
- Latency-critical ML inference остаётся в Python/native runtime: перенос
  Whisper, LLM runtime или OmniVoice в JVM ухудшил бы переносимость моделей и
  добавил бы сериализацию в аудиотракт.
- Java core имеет executable stdio JSONL 1.0, строгие схемы и атомарный
  SQLite-журнал идемпотентности. macOS и Windows backend запускают его до
  первого LLM-вызова и сверяют metadata-only решения о фактическом маршруте и
  уровне автономности с Python-политикой; prompt, транскрипты, документы и
  credentials через этот IPC не проходят. Обе сборки содержат ограниченный
  `jlink` runtime, а CI проверяет
  Python ↔ Java golden contracts на Linux, macOS и Windows. При недоступности
  companion интерфейс явно показывает резервную Python-политику; несовпадение
  решений блокирует запрос. На macOS внешний маршрут дополнительно допускается
  только для данных уровня `public` после явного выбора. Перед вызовом любого
  подключённого production-коннектора общий integration hub получает Java claim,
  а после вызова фиксирует metadata-only результат. Незавершённое действие при
  старте только сверяется через `action.inspect` и connector idempotency lookup;
  слепого автоматического повтора нет. Если Java-журнал недоступен, внешнее
  изменение блокируется.

Точное решение и границы миграции описаны в
[`docs/ADR-0001-CROSS_PLATFORM_JAVA_CORE.md`](docs/ADR-0001-CROSS_PLATFORM_JAVA_CORE.md),
а честная матрица Windows — в [`windows/README.md`](windows/README.md).

## Стек по умолчанию

- STT: `whisper-large-v3-turbo`, MLX, русский язык.
- LLM по умолчанию: `Qwen3-4B-Instruct-2507`, 4-bit, MLX; опционально — явно
  настроенная OpenAI-совместимая API без скрытого переключения маршрута.
- TTS: `OmniVoice 0.6B`, Q8 GGUF, нативный GGML/Metal-сервер, русский язык.
- Turn detection: адаптивный energy VAD, 30-миллисекундные блоки.

Требования к памяти и ускорителю зависят от выбранных локальных моделей; перед
пилотом они проверяются на фактической матрице устройств, а не выводятся из
конфигурации одного компьютера.

## Установка

Нужны Homebrew, `uv`, CMake, PortAudio, JDK 21 и Gradle:

```bash
brew install cmake portaudio openjdk@21 gradle
uv sync --python 3.12 --extra dev
```

Для воспроизводимой нативной сборки OmniVoice нужна зафиксированная upstream
ревизия с submodules; проверенный patch применяется сборщиком автоматически:

```bash
git clone --recurse-submodules https://github.com/ServeurpersoCom/omnivoice.cpp vendor/omnivoice.cpp
git -C vendor/omnivoice.cpp checkout 4f33af825d66e6ef1cb185e87b4589cacf747291
git -C vendor/omnivoice.cpp submodule update --init --recursive
```

## Нативная macOS-утилита

Готовое самодостаточное приложение находится рядом с папкой проекта:
`RnD Workbench.app`. Оно показывает рабочее пространство ассистента и
остаётся доступным через иконку в menu bar.

Из основного окна или menu bar можно открыть компактное плавающее окно в правом
нижнем углу. В нём есть два режима: «Голос» с управлением прослушиванием и
перебиванием и «Чат» с последними сообщениями и строкой ввода. Окно остаётся
поверх других приложений, перемещается перетаскиванием за фон и разворачивается
обратно в полное рабочее пространство. Полный и компактный вид — два состояния
одного приложения: переход закрывает предыдущее окно и сохраняет общий черновик.
Комбинация `⌘⇧M` указана рядом с командой
компактного окна в меню приложения.
Полное и компактное окна используют одну настройку озвучивания
`rnd.speakReplies`; кнопка с динамиком одновременно переключает её в обоих
режимах. Если TTS недоступен, готовый текст остаётся в истории, а задача
завершается успешно. В интерфейсе появляется неблокирующий баннер с командой
«Повторить озвучивание»: она воспроизводит последний ответ повторно, не вызывает
LLM и не создаёт новую задачу или сообщение в базе.
Первый запуск может запросить доступ к микрофону. В голосовом режиме ассистента
можно перебить обычной речью: озвучка остановится, а новая реплика сразу пойдёт
в Whisper. Прерванная фраза помечается в истории как «перебито».

По умолчанию голосом произносится одна законченная реплика до 220 символов, а
полный ответ остаётся в чате. Она синтезируется одним запросом OmniVoice: это
устраняет смену тембра между предложениями и звуковой стык нескольких независимо
сгенерированных фрагментов. Двоеточие и точка с запятой не считаются концом
реплики, поэтому заголовок не отрывается от следующей мысли.

Пересобрать приложение после изменения SwiftUI или Python backend:

```bash
zsh macos/build.sh
```

Сборщик компилирует OmniVoice под Metal, включает runtime, зависимости, исходный
код и локальные модели внутрь пакета приложения и подписывает его ad-hoc подписью.

Проверка окружения:

```bash
uv run local-voice --self-test
uv run local-voice --list-devices
uv run local-voice --loopback-test
```

Запуск:

```bash
uv run local-voice
```

macOS запросит доступ к микрофону для Terminal или Codex. VAD начинает слушать
сразу с безопасным стартовым порогом и адаптируется в фоне только по явно
подпороговым блокам, поэтому первую реплику можно произносить без паузы.

Глобальная диктовка включается удержанием правой `⌥`: отпускание клавиши
завершает запись и вставляет распознанный текст в текущее редактируемое поле.
Парольные и защищённые поля отклоняются. Резервный путь не использует системный
буфер обмена: Unicode-событие отправляется только захваченному приложению, а
неподтверждаемая вставка сохраняет проверочную копию в черновике RnD Workbench.
Зависший аудиопоток и STT ограничены по wall-clock и не могут вставить частичный
результат после отмены.

Один голосовой запрос и выход:

```bash
uv run local-voice --once
```

Проверка без микрофона и Whisper:

```bash
uv run local-voice --text "Коротко объясни, почему небо синее"
```

## Настройка

Все параметры находятся в `config.toml`. Если выбрано неверное устройство:

```bash
uv run local-voice --list-devices
```

Затем укажите индексы:

```toml
[audio]
input_device = 1
output_device = 2
```

В шумной комнате увеличьте `noise_multiplier` до `4.0`. Если начало тихой речи
не ловится, уменьшите `min_rms` до `0.003` и `noise_multiplier` до `2.2`.

Для TTS по умолчанию оставлен 14-процентный запас по уровню (`output_gain = 0.86`).
Перед выводом работает лимитер с потолком 0.94. Весь ответ проигрывается через
один CoreAudio stream, а следующая фраза синтезируется параллельно текущему
воспроизведению: аудиоустройство больше не закрывается и не открывается на каждой
границе предложения. Если конкретные динамики всё ещё звучат жёстко, уменьшите
`output_gain` до `0.75`–`0.80`.

OmniVoice запускается как постоянный локальный сервер только на `127.0.0.1`.
Параметр `steps = 16` даёт быстрый режим, а `chunk_duration_s = 1.5` ускоряет
освобождение генератора после перебивания. В A/B-проверке контрольный WAV
оказался побитно идентичен варианту 2,5 с. Дополнительная кооперативная отмена
нативного сервера устранила фоновую генерацию уже перебитой реплики. Для
desktop-realtime профиля внутренний crossfade
сокращён до 60 мс (20 мс fade-out, 20 мс защищённой паузы, 20 мс fade-in), а
краевой fade/pad — до 20 мс. Исходный профиль доступен для мгновенного отката:

```bash
OMNIVOICE_STREAM_POSTPROC_PROFILE=upstream uv run local-voice
```

В A/B тесте desktop-профиль синтезировал 17,43 с речи за 4,42 с (RTF 0,253),
сократил суммарную длительность той же реплики на 0,4 с, сохранил пик 0,906 и
0 обрезанных сэмплов. Whisper одинаково распознал обе версии.

Репрезентативный контроль формата production-ответа — одна законченная фраза —
дал первый аудиоблок через 0,706 с, 3,55 с речи за 0,707 с (RTF 0,199), peak
0,789551, 0 clipped samples и 0 click candidates. После подтверждённого
перебивания фактический `AudioPlayer` остановился за 0,116 с, а первый блок
восстановленного ответа пришёл через 1,360 с. Обратная проверка Whisper дала
WER 0. Многофразовые ответы намеренно не используются для TTS: полный текст
остаётся в чате.

Проект `pavanyellow/omnivoice-fast` с заявленными 115 мс рассчитан на CUDA/H100
и vLLM и не запускается на macOS. Здесь используется быстрый нативный порт
`ServeurpersoCom/omnivoice.cpp` для Metal с теми же весами OmniVoice.

Перебивание включено через `assistant.barge_in_enabled`. Оно срабатывает примерно
после 300 мс близкой речи. Во время воспроизведения действует отдельный абсолютный
порог `barge_in_playback_min_rms = 0.032`, а адаптивный порог учитывает утечку и
громкость фактически проигрываемых блоков TTS. Ссылка на громкость удерживается
500 мс, чтобы перекрыть короткие паузы между потоковыми фрагментами, а первые
600 мс ответа используются для калибровки только по блокам ниже порога речи.
Очевидная близкая речь может перебить ассистента и в этом раннем окне, а буфер
сохраняет подтверждающие 300 мс и pre-roll для Whisper. Эти ограничения не
применяются, пока модель только формирует ответ, поэтому перебивание без
звучащего TTS остаётся чувствительным. С наушниками оно ещё надёжнее.

Если помощник всё равно перебивает сам себя, сначала увеличьте
`barge_in_playback_min_rms` до `0.04`, затем при необходимости
`barge_in_echo_multiplier` с `2.1` до `2.3`. Если он плохо слышит тихое
перебивание — уменьшите абсолютный порог до `0.025`, не меняя обычный `min_rms`.

### Внешняя языковая модель

В «Настройках» можно выбрать «Внешняя API», указать HTTPS-адрес
OpenAI-совместимого `/chat/completions`, идентификатор модели и API-ключ.
Удалённые адреса требуют HTTPS; незашифрованный HTTP разрешён только для
loopback-адреса на том же устройстве. В текущем macOS-референсе ключ
привязан к каноническому endpoint и хранится в Связке ключей, а не в
SQLite, событиях или логах.

По умолчанию внешней модели доступны системные и служебные инструкции, название
текущего пространства, активный скилл, запрос, история текущей задачи и только
вручную прикреплённые или явно `@`-упомянутые источники. Расширение до контекста
пространства требует отдельного выбора и сбрасывается при смене endpoint или
пространства. Автоматизации продолжают выполняться локальной MLX-моделью.

### Быстрый системный TTS

Для отладки без загрузки нейросетевого TTS:

```toml
[tts]
backend = "macos"
voice = "Milena"
```

Имена установленных голосов можно посмотреть командой `say -v '?'`.

Для возврата к прежнему Qwen3-TTS укажите `backend = "qwen3"`, модель
`models/qwen3-tts`, язык `Russian` и голос `Serena`.

## Идентичность агента

Системный промпт хранится в `config.toml` и продублирован безопасным значением по
умолчанию в `src/voice_assistant/config.py`. Он объясняет модели, что она —
локальный RnD Workbench, принимает голос и текст, знает о рабочих пространствах,
задачах, памяти, документах, локальном поиске, skills, артефактах, автоматизациях
и согласованиях. Промпт также явно фиксирует границу: прямого function calling у
LLM пока нет, поэтому она не должна выдавать UI-операцию или черновик за
выполненное действие.

## Задержка

Приложение распознаёт законченную реплику после 650 мс тишины. Текст LLM
генерируется потоково; готовые фразы сразу передаются TTS в отдельном потоке,
поэтому озвучка начинается до завершения всего ответа. Фактическая задержка
зависит от длины запроса, температуры устройства и первого прогрева моделей.

Во время генерации и озвучивания микрофон остаётся активным. VAD использует
сразу установленный адаптивный порог: запуск не поглощает первую секунду речи,
а фоновая оценка обучается только по явно подпороговым блокам. Во время ответа
grace-период и playback reference оценивают утечку голоса ассистента; обнаружив
более близкую речь, система отменяет LLM/TTS и сохраняет начало новой реплики.
TTS выводится блоками по 30 мс, поэтому подтверждённое перебивание глушит звук
почти сразу. Это лёгкая защита от эха, а не полноценный AEC: на высокой
громкости встроенных динамиков может потребоваться настройка порога.

## Тесты

```bash
uv run pytest
```

Полный Python/UI-набор содержит **470 тестов** и проходит локально; в него входят
30 macOS и 76 Windows contract-тестов, а также Python ↔ Java golden contracts.
Отдельно проходят 45 JUnit-тестов Java 21 core.
Платформенные оговорки зафиксированы в `CURRENT_STATE.md`. Electron
`node --check`, endpoint-canonicalization self-tests и строгая рекурсивная
проверка подписи `.app` входят в релизный чек-лист. Пользовательская live-база и
её статистика намеренно не публикуются.

Windows Electron lockfile зафиксирован на Electron 44.0.0 и electron-builder
26.15.3; `npm audit` сообщает 0 известных уязвимостей.

Backend сообщает отказ озвучивания отдельными событиями `speech_error` и
`speech_recovered`; финальное событие ответа содержит `spoken` и `tts_error`.
Эти контракты и повторная озвучка без нового LLM-запроса и без записи в базу
покрыты regression-тестами.

Контрольный синтез с метриками и WAV:

```bash
PYTHONPATH=src .venv/bin/python scripts/benchmark_omnivoice.py --verify-stt
```

По контрольному скриншоту окна 1060×720 исправлено переполнение русских подписей:
заголовок события допускает две строки, действие вынесено в нижний ряд и не
сжимается, а верхняя панель выбирает компактную подпись. Полная ручная проверка
VoiceOver и всех состояний остаётся отдельным релизным шагом.

новом сеансе Codex, чтобы конфигурация MCP была перечитана. Интеграция
обслуживает только контекст разработки и не входит в runtime приложения.
